Preparing a fresh Ubuntu|We start on a freshly provisioned Ubuntu 24.04 server on IBM Cloud. rocks BNK cuddle only requires Terraform and helm to be installed locally — everything else is built in.
Installing roksbnkctl|We download the latest rocks BNK cuddle release binary and install it — one self-contained binary, no toolchain required.
Configuring the workspace|The entire deployment is described by a single declarative config file. We seed the workspace from it, with no interactive prompts.
runner container|The runner container bundles everything rocks BNK cuddle needs — Terraform, helm, and all the tooling are already inside it, so nothing has to be installed on the host. A single docker run does everything a CI job needs.
Configuring declaratively|The entire deployment is one declarative config file, checked into the repository. There are no prompts, and secrets stay in the CI environment.
Build the ROKS cluster|We could build every phase automatically, in one step and with no interaction, using a single rocks BNK cuddle up. But in this demonstration we drive each phase independently. We begin by building the cluster. You could instead point rocks BNK cuddle at the name of an existing IBM ROKS cluster.
Register with BNK Forge|At this point we can register our IBM ROKS cluster with BNK Forge. Let's do that.
Install BIG-IP Next|Next we install big IP next for cuber net tees, and license it.
testing framework|Next we build out the testing framework host, and run basic tests.
Remove BIG-IP Next|Now we remove big IP next for cuber net tees by downing that phase. The cluster keeps running.
Rebuild BIG-IP Next|Now we can independently rebuild the big IP next for cuber net tees phase — for example, to test a new version — on the same running IBM ROKS cluster.
Remove all phases|Finally, a single down command removes any or all of the phases — including the cluster itself.
Back where we started|We are back where we started, using rocks BNK cuddle as a single-binary deployment tool.

# ── Demo #3 (far-demo.sh): mirroring FAR into a private OCI registry ─────────
Preparing the demo host|An air-gapped cluster cannot reach the F5 Artifact Repository, so every chart and image a deployment needs must first be copied into a registry you control. We start on a plain Ubuntu host; the only dependency rocks BNK cuddle adds is helm, which it uses to pull the classic-Helm charts in the bill of materials.
Install the roksbnkctl binary|We install the same single rocks BNK cuddle binary. The mirror is built in — there is no separate tool to learn.
Seed a workspace for the mirror|The workspace needs only three things to mirror: the manifest version for big IP next for cuber net tees, the address of the F5 Artifact Repository, and the name of the auth tarball that unlocks it. Notice there is no credential in this file, and no cluster is created. Replication reads the manifest, pulls from F5, and pushes to your registry — a running cluster is never involved.
Pull the FAR credential from COS|So where does the credential come from? It is an auth tarball in the orchestration bucket on IBM Cloud Object Storage, and rocks BNK cuddle reads it straight from there. Here it lists the bucket, and there is the F5 far auth key tarball. Notice the bucket lives in the us south region while our workspace does not — rocks BNK cuddle resolves each bucket's own region, so this just works. The credential is never pasted into a config, never typed, and never leaves as a file.
The bill of materials|Now rocks BNK cuddle pulls that auth tarball from COS to authenticate, reads the F5 manifest, and derives the exact bill of materials — every chart and every image the install will pull, pinned by digest. Eighty-eight artefacts: sixty-two images and twenty-six charts. That is the contract the mirror has to satisfy.
Point the workspace at the mirror|Our target is a standard open-source Harbor registry, already running. Any O C I compliant registry would do — rocks BNK cuddle does not care which. Four fields select it: the kind, the host, the project the artifacts nest under, and the user. The password is piped in on standard input, so it never appears in the command line or in your shell history. Read it back, and the password shows only as set.
What replication would copy|Diff compares the bill of materials against what the mirror already holds, so you can see exactly what a replication would move before you move it. Our registry is brand new, so every artifact is missing.
Replicate FAR into the mirror|Now we copy. Each chart and each image is fetched from the F5 Artifact Repository and pushed into the registry by digest, so the copy is bit for bit identical to the source. Anything already present is skipped, which makes replication safe to re-run and cheap to resume.
Verify every mirrored artifact|Copying is not the same as being correct. Verify walks the bill of materials again, and for every single artifact confirms it is present in the mirror and that its digest matches the source exactly.
Browse the mirror|Every chart and every image that a big IP next for cuber net tees install needs now lives in a registry you control. From here, an air-gapped install pulls from this host and never reaches out to F5 — with one rocks BNK cuddle workspace, and no cluster.

# ── Demo #4 (flp-licensed-demo.sh): a shared licensing cluster ───────────────
Prepare the host|One cluster will run the F5 license proxy and hold the only path out to F5. A second cluster will install big IP next for cuber net tees entirely from a private registry, and license through that proxy — reaching neither the F5 artifact repository nor F5's licensing service. We start on a plain Ubuntu host; rocks BNK cuddle needs only terraform and helm locally, and internalises everything else.
Register the services cluster|Both clusters are already running. rocks BNK cuddle does not have to build them — it can adopt a cluster you already own. Notice create is false: this workspace names an existing cluster rather than provisioning one. Register looks it up in IBM Cloud and records its identity. Nothing is provisioned, and it takes a second rather than forty minutes.
Replicate FAR into the private registry|Now we point the workspace at the private registry — four fields, with the password piped in on standard input so it never appears in the command line. rocks BNK cuddle reads the F5 manifest and derives the exact bill of materials: every chart and every image the install will pull, the license proxy among them. Then it copies each one from the F5 artifact repository into our registry, by digest, so the copy is bit for bit identical to the source. From this point on, nothing is ever pulled from F5.
Deploy the F5 License Proxy with NodePort access|The license proxy is a cluster wide licensing broker, and it is the only component that needs to reach F5. So we deploy it once, here, and let other clusters license through it. The add node port access flag is what makes that possible: it exposes the proxy beyond this cluster, it puts the worker node addresses into the proxy's own certificate — without them the remote cluster would reject the handshake — and it opens the port to the other cluster's network, and nothing else. The proxy now answers on every worker node, and every one of those addresses is in its certificate.
Register the application cluster|A second workspace, for the second cluster — also already running, also simply registered. Its licence mode is F five license proxy, and the external block points at the proxy in the OTHER cluster: its address, and its root certificate authority, both read straight out of the first workspace. This cluster never runs a license proxy of its own. It uses the same private registry, which is already full, so there is nothing left to copy.
Deploy BIG-IP Next from the registry|Now we install big IP next for cuber net tees. Every chart and every image comes from the private registry, and the C N E instance is told to pull from it too. The cluster wide controller trusts the remote proxy's certificate and brokers the licence through it — across to the other cluster, and never out to F5.
Confirm the remote FLP licensed the cluster|The licence custom resource tells the story: mode F five license proxy, and state Active — licensed by a proxy that is not even in this cluster. The C N E instance is reconciled and the dataplane is running. And look here: there is no license proxy in this cluster at all. It only ever spoke to the registry, and to the proxy next door.
Remove the workloads, leave the clusters|Both clusters were registered, never created — so rocks BNK cuddle removes only what it installed and leaves them running. One proxy, one registry, and any number of air-gapped clusters licensing through them.
A CI runner with nothing installed|This is a continuous integration runner, and nothing is installed on it. No roksbnkctl, no terraform, no helm, no kubectl. Every step you are about to see is a single docker run of the tools runner image. That is all a pipeline ever needs.
Job one — configure from the environment|The first job owns the licence proxy. There is no configuration file anywhere. The workspace is built entirely from environment variables: where the cluster is, where the private registry is, and the credential to reach it. The password comes from the secret store and is never written into the pipeline.
Mirror F5's registry into the private one|roksbnkctl reads F5's manifest and derives every chart and every image the install needs. It replicates them into your own registry. The licence proxy is in that list, so even the licensing component comes from your registry, not from F5.
Deploy the License Proxy from the container|Now deploy the proxy. It is the only component that needs to reach F5, so it runs once, here, exposed so the other cluster can license through it. Pass every zone's prefix: a multi-zone network has one per zone, and a pod scheduled in a zone you left out is silently dropped. The chart needs fixing up before it will install on OpenShift, and roksbnkctl post-renders it itself, so the container needs no interpreter at all.
Hand the proxy to the next job|Here is the whole handoff. Two values: the proxy's address, and its root certificate. A pipeline prints them as job outputs and the next job receives them as environment variables. Nothing else is passed between the jobs.
Job two — install BIG-IP Next|The second job installs BIG-IP Next for Kubernetes. Same private registry, and licence mode set to F5 licence proxy, pointed at the proxy it just received. Every chart and every image comes from the registry. This cluster has no route to F5 at all.
Confirm the pipeline licensed the cluster|The licence resource: mode F5 licence proxy, state Active. Issued through a proxy that is not in this cluster. A pipeline gates on exactly this. The data plane is up, pulled entirely from the private registry, and there is no licence proxy here at all.
Remove only what the pipeline installed|Both clusters were registered, never created, so the pipeline removes only what it installed and leaves them running. A disconnected install, licensed remotely, from a runner with nothing on it.
