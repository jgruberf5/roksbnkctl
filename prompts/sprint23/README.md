# Sprint 23

**Theme:** Phase-separation leak fix in `bnk-phase-override.tfvars`. A normal post-`up` Split trial state carries two managed cluster-shared resources (`module.testing.tls_private_key.jumphost_shared_key`, `module.roks_cluster.module.cluster.ibm_resource_instance.cos_instance`) that the override produced by `writeAndInitSecondPhase` fails to suppress. The header comment on `internal/orchestration/second_phase_reuse.go` claims the override turns "ALL cluster-shared creation off" — that claim is inaccurate per 2026-05-27 live evidence. Pre-Sprint 22 the DetectShape false-positive masked this leak; post-fix it's a real `roksbnkctl bnk down` resource-damage hazard (the registry COS instance + the jumphost shared key would be destroyed alongside the BNK trial). Sprint 22's `v1.7.1` tag is GATED on this fix; the two sprints ship together.

_Surfaced 2026-05-27 during the Sprint 22 down-prompt + DetectShape live verify against canada-roks. Full live evidence + investigation hypothesis in `issues/issue_sprint23_staff.md`. Filed during the same conversation that shipped Sprint 22's staff fixes (`18415eb`, `cbb9c1b`); held off from in-conversation fix because the investigation depends on reading HCL count-gates carefully and the right intervention (gate upstream vs. add another override flag) isn't obvious from the symptom alone._

## Integrator decisions baked in (do not relitigate)

Don't pre-commit to a fix shape before reading.

The acceptance criterion is `jq '.resources[] | select(.mode == "managed" and (.module | startswith("module.roks_cluster") or startswith("module.testing")))' ~/.roksbnkctl/<ws>/state/terraform.tfstate` returns empty after a fresh `up` against a real workspace. The integrator runs the `!` verify; validator documents the recipe but does not execute it.
4. **v1.7.1 unblocks here.** Sprint 22's staff fixes are already shipped; this sprint's fix is the last gate. The combined `v1.7.1` CHANGELOG entry covers down-prompt + DetectShape + phase-separation fixes from BOTH sprints.
