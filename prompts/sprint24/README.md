# Sprint 24

**Theme:** `roksbnkctl test hosts {list,add,remove,clear}` CLI surface. The workspace's `test.connectivity.extra_hosts` slice — the field that drives both `test connectivity` and (no-flag) `test dns` — has no CLI for management today; the only path is hand-editing `~/.roksbnkctl/<workspace>/config.yaml`. Other workspace-config surfaces with comparable shape (`targets`, `cluster register`) have first-class CLI. This sprint closes the asymmetry by adding four subcommands that mirror `targets`' ergonomic.

_Filed 2026-05-27 as a future-sprint placeholder behind Sprint 23 (the resource-damage class), then promoted into the `v1.7.1` release scope on the same day per the integrator's decision to bundle the UX gap alongside the Sprint 22 + 23 safety fixes. The error message the test commands themselves emit when no hosts are configured — `internal/cli/test.go:803` reads "no hosts configured to probe; add to test.connectivity.extra_hosts in config.yaml" — literally points operators at YAML editing today; closing this Issue lets that error point at the new CLI instead._

## Integrator decisions baked in (do not relitigate)

1. **Tight scope: only `test.connectivity.extra_hosts`.** The `test.dns.{default_target,resolvers}` and `test.throughput.*` config fields have working flag-driven equivalents (`--target`, `--server`, `--duration`, etc.) and adding CLI for them is a separate scope decision deferred to a later sprint. Do NOT expand this sprint to cover them.
2. **Mirror `targets {list,add,remove}` ergonomics.** Same shape: `list` (one URL per line, JSON via `-o json`), `add <url>...` (idempotent, no-op on already-present), `remove <url>...` (idempotent, no-op on absent). Add a fourth subcommand `clear` (with `--auto`-skippable confirmation prompt) since the slice can grow and a "nuke all" affordance is operator-friendly.
3. **No edits to `RunE` business logic of the existing `test` commands.** The new subcommands sit under `test hosts` — `testCmd.AddCommand(testHostsCmd)`; `testHostsCmd.AddCommand(listCmd, addCmd, removeCmd, clearCmd)`. The existing `test connectivity` / `test dns` / `test throughput` / `test list` commands keep their current shape.
4. **`internal/cli/test.go:803`'s error message is part of staff's scope.** Update from the YAML-editing prompt to point at the new CLI surface: `"no hosts configured to probe; add via roksbnkctl test hosts add <url>"` (exact wording staff's call). This is the operator's first contact with the gap; closing it is part of "the CLI exists".
5. **Tech-writer covers Sprint 23 round-2 + Sprint 24 in ONE pass.** Sprint 23's round-1 tech-writer GREEN (`158ae55`) predated the round-2 fix (`e4b7f7b`). Rather than re-dispatching tech-writer for Sprint 23 alone, the round-2 re-sweep folds into Sprint 24's tech-writer scope. Tech-writer's GREEN verdict at the end of this sprint unblocks the `v1.7.1` cut covering Sprint 22 + 23 + 24.
6. **`live-verify-high-issues` does NOT apply to this sprint.** UX feature, hermetic test class sufficient. Sprint 23's round-2 work is already live-verified (per its closure section in PLAN.md); the tech-writer's re-sweep here is documentation-drift verification, not a re-verify of the architectural fix.
