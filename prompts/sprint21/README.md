# Sprint 21

**Theme:** Cobra/pflag argv-parser strictness — every non-positional flag must be followed by either `=value` (no whitespace) OR ` value` (a single space, value is the next argv token). The stuck-together shorthand `-fvalue` form (and structurally-similar typos like `-ws`, `-vf`, `-os`) must be rejected at parse time with an actionable error. First regular work sprint post-`v1.6.4`, runs in parallel with Sprint 20 (release-publish hardening) — independent scopes, no shared files.

_Drafted from the integrator's 2026-05-21 live-use observation. The operator typed `roksbnkctl init -ws canada-roks --var-file ./terraform.tfvars` intending `--workspace canada-roks`. Cobra/pflag's stuck-together-shorthand parser interpreted `-ws` as `-w` with value `s`; the positional `canada-roks` was silently dropped because `init` did not declare `Args: cobra.NoArgs`. A workspace literally named `s` was created at `~/.roksbnkctl/s/` carrying the correct `canada-roks` cluster identity inside its `config.yaml` and a full `terraform.tfvars.user` copy at the workspace root — Sprint 19's deliverable worked, for the wrong workspace name. A subsequent bare `roksbnkctl cluster up` then resolved to `current_workspace: default` (a stale workspace from prior cycles) and produced a 25-resource-destroy / 41-resource-add plan against real cloud state. The operator caught the plan before applying; tooling silence allowed the typo to traverse multiple commands before surfacing. Sprint 21 makes the typo surface immediately at the bad argv, before any RunE runs, before any workspace dir is created._

## Integrator decisions baked in (do not relitigate)

1. **Parser strictness contract.** Every non-positional flag's value must be passed in one of exactly two shapes: `--flag=value` / `-f=value` (immediate `=`, no whitespace), OR `--flag value` / `-f value` (one space, value is the next argv token). The stuck-together short-flag-value form (`-fvalue`, where `<value>` is non-empty and the immediately following character is not `=`) is **rejected at parse time** with an error that names BOTH the offending token AND the two acceptable forms.
2. **Pre-parse argv preflight.** The check belongs in the top-level binary entrypoint (`cmd/roksbnkctl/main.go`) or in `rootCmd.PersistentPreRunE`, **before** cobra dispatches to any RunE. The misparse must be caught before any side-effect (workspace creation, IAM verify, file write, network call) is initiated.
3. **List-of-known-value-shorts, not regex.** The preflight needs to know which short flags carry a value (so it can distinguish `-ws` (typo) from `-vvv` (legitimate bool stacking, if any boolean short flags exist)). Walk the cobra command tree once at preflight to collect the set of registered value-requiring short flags across the root + all subcommands; reject any argv token of the shape `-X<suffix>` where `X` is in that set AND `<suffix>` is non-empty AND `<suffix>[0]` is not `=`. The collected set is implementation-detail of the preflight — no hand-maintained list of typos.
4. **Position-aware: belt-and-suspenders.** Every command that does NOT accept positionals must declare `Args: cobra.NoArgs`. Audit the cobra tree under `internal/cli/` and add the constraint to `init`, `up`, `down`, `plan`, `apply`, `cluster up`, `cluster down`, `cluster register`, and every other command that today defaults to cobra's `ArbitraryArgs` and shouldn't. Commands that DO take positionals (`ws delete <name>`, `cos object get <key> <local>`, etc.) keep their existing `Args:` setting. This is the OTHER half of the typo class — it catches the silently-dropped `canada-roks` in the original failure.
5. **Error message names the recovery in concrete terms.** Reject with: `roksbnkctl: '-ws' looks like a stuck-together short-flag-value, which this binary does not accept; use '-w s' (space) or '-w=s' (equals) for short flags, or '--workspace=<name>' / '--workspace <name>' for long. Did you mean '--workspace canada-roks'?` The error must include the literal offending token, both acceptable forms, AND a best-guess "did you mean" using the binary's actual flag set so the operator can copy/paste the fix.
6. **Long-flag stuck-together is impossible (good).** Cobra's `--flag value` and `--flag=value` are the only two shapes for long flags; there's no `--flagvalue` form. The strictness rule applies only to short flags (`-X`). No work needed on the long-flag side beyond confirming the rule applies symmetrically.

## Reference — the operator failure in concrete terms

The 2026-05-21 sequence:

1. Operator typed `roksbnkctl init -ws canada-roks --var-file ./terraform.tfvars`.
2. Cobra/pflag parsed: `-w s` (value=`s` via stuck-together shorthand), positional=`canada-roks` (silently dropped — init's `Args:` was cobra's default `ArbitraryArgs`), `--var-file ./terraform.tfvars` (correct).
3. `runInit` ran against workspace=`s`. Sprint 19 worked correctly for THAT workspace: `~/.roksbnkctl/s/config.yaml` with `name: canada-roks`, `~/.roksbnkctl/s/terraform.tfvars.user` with the full 6.4 KB var-file copy.
4. Operator ran `roksbnkctl cluster up` (no `-w`). Resolved to `current_workspace: default` (an unrelated workspace from earlier cycles).
5. `default`'s `terraform.tfvars.user` did NOT exist; `default`'s `config.yaml` had defaults; the plan rendered with module defaults: `roksbnkctl-demo` / `tf-tgw` / `tf-testing-vpc`. The state file in `default/state-cluster/` carried 25 real-cloud resources from a prior cycle named `canada-roks*`. Plan diff: 25 destroy + 41 add.
6. Operator caught the plan at review and stopped before `apply`.

Sprint 21's hardening would have surfaced the typo at step 1 — before any workspace dir was created, before any cluster phase ran, before terraform was invoked. The follow-on `cluster up` resolution against the stale `default` workspace is a separate concern Sprint 21 does NOT close — that's `current_workspace` UX, possibly its own future sprint. Sprint 21 is purely the parse-time strictness contract.
